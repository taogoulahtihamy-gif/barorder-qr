Implement professional real-time notifications for BarOrder.

Goal:
Improve notifications for both customer and admin/staff.

Do NOT break:
- orders
- kitchen
- checkout
- QR table flow
- roles
- restaurants
- socket sync
- build

==================================================
1. CUSTOMER ORDER STATUS NOTIFICATIONS
==================================================

When a customer places an order, they must receive status notifications for:

- order accepted
- order preparing
- order ready
- order served
- order paid
- order cancelled

Customer must be notified even if they are not currently on the order tracking page, as long as:
- the site tab is still open
- or the PWA/browser allows notifications

Implement:
- browser notification permission request
- sound notification
- vibration on mobile
- toast inside app
- localStorage persistence of active orderId

Use:
navigator.vibrate([200, 100, 200]) if available.

If vibration is not supported:
- fail silently
- do not crash

==================================================
2. CUSTOMER ACTIVE ORDER TRACKING
==================================================

After checkout:
- save active order in localStorage:
  activeOrderId
  activeRestaurantSlug
  activeTableId

On app load:
- if active order exists, listen for its status updates
- show notification if status changes

This must work even if customer is on:
- menu
- cart
- welcome page
- assistance page

==================================================
3. BROWSER/PWA NOTIFICATIONS
==================================================

Create notification helper:
client/src/services/notificationService.js

Functions:
- requestNotificationPermission()
- notifyCustomerOrderStatus(order)
- notifyAdminNewOrder(order)
- notifyKitchenOrder(order)
- playNotificationSound()
- vibrateDevice()
- showToast()

Rules:
- request permission after user interaction, not automatically on first load
- show small prompt/button if permission not granted:
  FR: Activer les notifications
  EN: Enable notifications

==================================================
6. FRONTEND SOCKET LISTENERS
==================================================

Create centralized realtime listener:
client/src/services/realtimeNotificationService.js

It should:
- connect once
- avoid duplicate listeners
- cleanup properly
- route notifications by role and restaurant_id
- ignore unrelated restaurants
- ignore repeated duplicate events

Deduplication:
- keep last notified event id in memory/localStorage
- do not play sound twice for same event

==================================================
7. SOUND
==================================================

Use existing sound if available.

client/src/assets/sounds/new-order.mp3

Rules:
- sound must play only after user has interacted with page
- if browser blocks autoplay, show toast:
  FR: Touchez l’écran pour activer le son
  EN: Tap to enable sound

Add “Activer le son” / “Enable sound” button in admin header if needed.
