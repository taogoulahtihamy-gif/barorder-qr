Build a professional waiter call + realtime notification system in the existing BarOrder QR project.

IMPORTANT:
- Do not redesign the existing UI.
- Do not break working orders, payments, kitchen, dashboard, or QR flow.
- Keep current architecture.
- Apply changes directly to project files.

GOAL
Customers can press:
"Appeler un serveur"
from the table page/menu page.

Admins/staff instantly receive the call in realtime.

FEATURES

1. Customer side
Routes:
- /r/:slug/table/:tableId
- /r/:slug/menu/:tableId

Add a working "Appeler un serveur" action.

When pressed:
- create a server_call record in PostgreSQL
- emit realtime socket event:
  new_server_call

Payload:
- restaurant_id
- table_id
- table_number
- message (optional)
- status = pending
- created_at

2. Backend
Create/check API routes:
POST /api/public/server-call
GET /api/admin/server-calls
PATCH /api/admin/server-calls/:id/status

Statuses:
- pending
- acknowledged
- resolved

3. Database
Use existing server_calls table if present.
If missing, create migration safely.

Required fields:
- id
- restaurant_id
- table_id
- table_number
- message
- status
- created_at

4. Realtime notifications
Emit:
- new_server_call
- server_call_updated

Kitchen/admin pages must listen.

5. Admin notification center
Create:
- bell notification icon in admin header
- realtime badge counter
- dropdown list of latest waiter calls

6. Admin waiter calls page
Create:
/admin/server-calls

Features:
- pending calls
- acknowledge
- resolve
- filter by status
- sort newest first

7. Kitchen integration
On /admin/kitchen:
- show floating notification/toast for new waiter calls
- subtle sound notification
- clickable shortcut to call list

8. Customer feedback
When customer presses button:
- show success toast:
  "Un serveur arrive bientôt"
- disable spam clicking for 30 seconds

9. Mobile responsive
Must work perfectly on iPhone/mobile.
No overflow.

10. Cleanup
- no mock data
- no fake calls
- no console spam
- remove duplicate listeners

11. Build
Run npm run build and fix all errors.

ACCEPTANCE TEST
- customer presses "Appeler un serveur"
- admin instantly sees notification
- kitchen sees toast/sound
- call appears in /admin/server-calls
- admin can acknowledge and resolve
- realtime updates everywhere
