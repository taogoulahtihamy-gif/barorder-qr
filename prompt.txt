Implement multi-restaurant management for BarOrder QR progressively and safely.

Goal:
Transform BarOrder into a real multi-restaurant SaaS platform.

IMPORTANT:
Do NOT break the existing restaurant “Le Palais”.
Do NOT delete existing data.
Do NOT break:
- login
- roles
- orders
- kitchen
- products
- categories
- tables
- QR
- payments
- promotions
- server calls
- dashboard
- client menu

==================================================
1. CREATE RESTAURANTS ADMIN PAGE
==================================================

Create page:
 /admin/restaurants

Visible only to:
- super_admin

Sidebar label:
FR: Restaurants
EN: Restaurants

Features:
- list restaurants
- add restaurant
- edit restaurant
- activate/deactivate restaurant
- view restaurant details

Restaurant fields:
- name
- slug
- address
- phone
- currency
- primary_color
- logo_url
- is_active

Design:
- premium admin style
- mobile responsive cards
- desktop table/list
- no horizontal overflow

==================================================
2. BACKEND RESTAURANT CRUD
==================================================

Create admin endpoints:

GET /api/admin/restaurants
POST /api/admin/restaurants
PATCH /api/admin/restaurants/:id
PATCH /api/admin/restaurants/:id/status

Validation:
- name required
- slug unique
- currency default FCFA
- primary_color default #d4a843
- is_active default true

Do not allow non-super_admin to create restaurants.

==================================================
3. DATABASE SAFETY
==================================================

Ensure restaurants table exists.

Use safe migration only:
CREATE TABLE IF NOT EXISTS restaurants ...

Do not drop existing table.

Ensure Le Palais exists:
- name = Le Palais
- slug = le-palais
- currency = FCFA
- is_active = true

==================================================
4. RESTAURANT_ID ISOLATION
==================================================

Audit and ensure restaurant_id exists on:
- users
- products
- categories
- tables
- orders
- order_items if needed
- payments
- promotions
- server_calls

Use:
ALTER TABLE ... ADD COLUMN IF NOT EXISTS restaurant_id INTEGER REFERENCES restaurants(id)

Do not delete data.

For existing data:
- set restaurant_id to Le Palais id when null.

==================================================
5. ROLE-BASED ACCESS
==================================================

super_admin:
- sees all restaurants
- can create/edit restaurants
- can create admins for any restaurant

admin/manager:
- sees only their restaurant data

waiter/kitchen/cashier:
- sees only their restaurant data

Do not expose other restaurants’ data.

==================================================
6. USERS RESTAURANT ASSIGNMENT
==================================================

In /admin/users:
- super_admin can choose restaurant when creating/editing user
- admin can only create users for their own restaurant
- non-super_admin cannot assign another restaurant

Add restaurant column/display:
- restaurant name

==================================================
7. CLIENT ROUTING
==================================================

Keep existing route:
 /r/:slug/table/:tableId

It must load restaurant by slug.

If restaurant inactive:
show:
FR: Ce restaurant n’est pas disponible actuellement
EN: This restaurant is currently unavailable

If slug not found:
show clean 404.

9. QR TABLES
==================================================

 /r/:slug/table/:tableId

Super_admin can filter by restaurant.

10. DASHBOARD/STATS FILTERING
==================================================

Every dashboard/statistic query must filter by restaurant_id.

super_admin:
- can optionally filter by restaurant

admin:
- only own restaurant
