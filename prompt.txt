Implement proper restaurant table status management.

Goal:
Make table statuses understandable, automatic, and manually editable.

Current problem:
Table statuses do not change automatically.
Admin cannot clearly change table status manually.
The meaning of “occupied/available” is unclear.

Do not break:
- QR codes
- menu
- orders
- kitchen
- payments
- roles
- responsive UI

1. Table statuses
Use these canonical statuses:
- available
- occupied
- waiting_payment
- reserved
- cleaning
- inactive

French labels:
- available = Disponible
- occupied = Occupée
- waiting_payment = En attente paiement
- reserved = Réservée
- cleaning = Nettoyage
- inactive = Inactive

English labels:
- available = Available
- occupied = Occupied
- waiting_payment = Waiting payment
- reserved = Reserved
- cleaning = Cleaning
- inactive = Inactive

2. Automatic status changes
When a new order is created for a table:
- set table status = occupied

When order status becomes served:
- set table status = waiting_payment

When order status becomes paid:
- set table status = available

When order is cancelled:
- if no other active order exists for same table, set table status = available

3. Manual admin status change
In /admin/tables:
Add a clear status dropdown/select for each table.

Admin/manager can manually set:
- Disponible
- Occupée
- Réservée
- Nettoyage
- Inactive

When changed:
- update database
- update UI immediately
- show success toast

4. Backend
Add or fix route:
PATCH /api/admin/tables/:id/status

Payload:
{
  "status": "available"
}

Validate status values.
Return updated table.

5. Frontend
In Tables page:
- show status badge with color
- show dropdown/change button
- show explanation tooltip:
  Disponible = table libre
  Occupée = client présent
  En attente paiement = commande servie non payée
  Réservée = table réservée
  Nettoyage = table à nettoyer
  Inactive = table non utilisée

6. QR behavior
If table status is inactive:
- customer QR page must show:
  “Cette table n’est pas disponible actuellement”
- do not allow ordering

If table is available/occupied/reserved/cleaning:
- keep current behavior, but show table status if useful.

7. Dashboard
Update table counters:
- available tables
- occupied tables
- waiting payment tables

8. Realtime
When table status changes:
emit:
- table_status_updated

Admin tables page and dashboard should update.

9. Bilingual
All labels must use i18n:
FR/EN.

10. Build and push.

Acceptance:
- creating order changes table to Occupée
- serving order changes table to En attente paiement
- paying order changes table to Disponible
- admin can manually change status
- badges translate FR/EN
- inactive table cannot accept orders
