Fix BarOrder realtime synchronization performance without removing features.

IMPORTANT:
- Do NOT rollback.
- Do NOT remove features.
- Do NOT break orders, kitchen, server calls, payments, promotions, QR, users, roles, print.
- Keep current premium design.

CURRENT ERROR:
AxiosError: timeout of 3000ms exceeded

CURRENT PROBLEM:
Too many pages refetch at the same time:
- orders
- kitchen
- payments
- server-calls
- dashboard

This slows the app and causes delayed synchronization.

==================================================
1. INCREASE API TIMEOUT
==================================================

Find the axios/API client.

Change timeout:
- production: 20000 ms
- development: 10000 ms

If request times out:
- do not clear existing data
- do not blank the page
- show small toast: “Synchronisation en cours…”
- retry silently

==================================================
2. PREVENT REFRESH STORM
==================================================

Create centralized refresh routing.

Do NOT trigger global refetch for every socket event.

Each socket event must refresh only the related page.

Rules:

A. new_order
Refresh only:
- admin orders
- kitchen
- dashboard

Do NOT refresh:
- payments
- server-calls
- users
- products
- tables

B. order_status_updated
Refresh only:
- admin orders
- kitchen
- dashboard

Do NOT refresh:
- server-calls
- users
- products
- tables

C. kitchen_updated
Refresh only:
- kitchen

D. server_call_created
Refresh only:
- server-calls
- dashboard

Also:
- notify waiter/admin/manager
- do NOT refresh orders
- do NOT refresh kitchen
- do NOT refresh payments

E. server_call_updated
Refresh only:
- server-calls
- dashboard

Do NOT refresh:
- orders
- kitchen
- payments

F. payment_updated
Refresh only:
- payments
- orders
- dashboard

Do NOT refresh:
- kitchen
- server-calls
- products

G. product_updated / category_updated
Refresh only:
- products
- categories
- client menu

Do NOT refresh:
- orders
- kitchen
- payments
- server-calls
